Two fields are required — the endpoint and the API key. Everything else has a default that works, and a bad value falls back to that default rather than failing.

## The two required fields

<ResponseField name="endpoint" type="string" required>
  The ingestion API base URL: `https://ingest.evpanda.io`. Must be `http` or `https`. The SDK appends the protocol route (`/v1/ocpp` or `/v1/ocpi`) itself — don't include it.
</ResponseField>

<ResponseField name="apiKey" type="string">
  Sent as the `X-API-Key` header. Falls back to the `EVPANDA_API_KEY` environment variable when unset; one of the two must be present. Must match the protocol — an OCPP client needs a charger network's key.
</ResponseField>

If either is missing or malformed, the client starts **inert**: every capture is a no-op, and the SDK reports the problem. Your service still boots.

<CodeGroup>
  ```go Go
  panda, err := evpanda.StartOCPP(evpanda.OCPPConfig{
      BaseConfig: evpanda.BaseConfig{Endpoint: "https://ingest.evpanda.io"},
  })
  if err != nil {
      log.Printf("evpanda: %v (running inert)", err) // always log this
  }
  ```

  ```ts Node
  const panda = OCPPClient.start({
    endpoint: "https://ingest.evpanda.io",
    debug: true, // the only way a config error is reported
  });
  ```

  ```python Python
  panda = OCPPClient.start(
      OCPPConfig(
          endpoint="https://ingest.evpanda.io",
          debug=True,  # the only way a config error is reported
      )
  )
  ```
</CodeGroup>

## All options

Field names differ by language convention; the behavior is the same everywhere except where noted.

| Purpose | Go | Node | Python |
| --- | --- | --- | --- |
| Ingestion base URL | `Endpoint` | `endpoint` | `endpoint` |
| API key | `APIKey` | `apiKey` | `api_key` |
| Buffer ceiling | `MaxBufferBytes` | `bufferCapacity` | `buffer_capacity` |
| Per-capture cap | `MaxCaptureBytes` | `maxCaptureBytes` | `max_capture_bytes` |
| Flush cadence | `FlushInterval` | `flushInterval` | `flush_interval` |
| Drain deadline | `DrainTimeout` | `drainTimeout` | `drain_timeout` |
| Compression codec | `Compression` | `compression` | `compression` |
| Log verbosity | `LogMode` | `debug` | `debug` |
| Log destination | `Logger` | `logger` | `logger` |
| Extra OCPI headers | `OCPIAllowedHeaders` | `ocpiAllowedHeaders` | `ocpi_allowed_headers` |

## Environment variables

| Variable | Read by | Effect |
| --- | --- | --- |
| `EVPANDA_API_KEY` | All SDKs | Supplies the API key when the config field is empty |
| `EVPANDA_LOG` | Go | `silent`, `errors`, or `debug`. Overridden by an explicit `LogMode` in config |

`EVPANDA_LOG` exists so an operator can silence the SDK during an incident with a restart, without a code change or a deploy.

## How bad values behave

Only `endpoint` and `apiKey` are hard-required. Every other option is a **tunable**: an out-of-range value falls back to its default and says so, rather than failing.

```
level=WARN msg="evpanda: config: `DrainTimeout` must be >= 5s; using default 10s"
```

That warning only appears where SDK logging is on — always in Go, and only with `debug` in Node and Python. A tunable typo in a silent Node client is invisible, which is a good reason to run staging with `debug: true`.

## Sizing the buffer

The buffer exists to absorb a delivery stall. Size it for how long you want to survive one.

<Steps>
  <Step title="Estimate your message rate">
    Count both directions. A 10,000-charger CSMS with a 60-second heartbeat plus normal status traffic runs around 400 messages per second; an OCPI server is usually orders of magnitude quieter.
  </Step>

  <Step title="Estimate the average captured size">
    OCPP frames are typically 200–800 bytes. OCPI exchanges are larger — a few KB — because they carry two bodies.
  </Step>

  <Step title="Multiply by the stall you want to ride out">
    `rate × size × seconds`. At 400 msg/s and 500 bytes, one minute of stalled delivery is about 12 MB. The 32 MiB Go default covers roughly two and a half minutes at that rate — enough for a blip, small enough for an ordinary container limit.
  </Step>

  <Step title="Check it against your container">
    The buffer is real resident memory. Set a ceiling your pod can actually afford, and watch the buffer gauges rather than guessing — see [Monitoring](/operate/monitoring).
  </Step>
</Steps>

<Warning>
  Don't set `MaxBufferBytes` below `MaxCaptureBytes`. A full-size capture could then never fit, so every large message would be dropped after being redacted. The Go SDK warns when you do.
</Warning>

## Choosing a flush interval

| Interval | Good for | Cost |
| --- | --- | --- |
| `500ms`–`1s` | Local development, integration debugging | Many small requests |
| `5s` (default) | Production | Balanced |
| `15s`–`30s` | Very high volume, cost-sensitive egress | Data is up to 30 seconds stale; more sits in the buffer at any moment |

A flush also fires early whenever a full batch of 1,000 messages is waiting, so on a busy CSMS the interval is rarely what triggers delivery.

## Compression

zstd is the default and is worth keeping: OCPI bodies and OCPP frames are JSON, which compresses extremely well.

- **Go** — zstd ships with the SDK.
- **Node** — zstd needs the optional `@mongodb-js/zstd` peer. Without it, the SDK silently uses gzip.
- **Python** — zstd needs the `evpanda[zstd]` extra. Without it, the SDK silently uses gzip.

Payloads below about 1 KB are sent uncompressed, where compression would cost more CPU than it saves bandwidth.
